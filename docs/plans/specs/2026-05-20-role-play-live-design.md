# Role-Play Live Feature — Design Spec
**Date:** 2026-05-20  
**Status:** Draft — awaiting user review  
**Scope:** ai-brain-orchestration + meet-mind (backend + frontend)

---

## 1. Problem Statement

Role-play exists today (`run_role_agent`, `PLAY_ROLE` route) but the experience is shallow:
- Jarvis plays the role for one reply, then reverts to normal
- No role session state (server or client)
- No UI affordances (quick-select, role badge, setup modal)
- Role hint is raw unclean user text — no character depth
- No proactive behaviour — Jarvis waits to be asked

This spec defines the flagship integration of role-play into live meetings.

---

## 2. Goals

1. **Custom role with rich character description** — user defines who Jarvis becomes
2. **Persistent role session** — Jarvis stays in character until explicitly told `"exit role"`
3. **Smart proactive intervention** — Jarvis speaks up at high-signal moments (decisions, risks, disagreements) without being asked
4. **Richer in-character responses** — structured, grounded in meeting transcript, with follow-up questions
5. **Clear UI** — role badge, setup modal, role-branded message bubbles

---

## 3. Non-Goals

- No preset roles library (pure custom role, user-defined)
- No WebSocket on ai-brain-orchestration (existing HTTP proxy pattern retained)
- No changes to existing routes (SUMMARY, NOTES, BRAINSTORM, HELP_DECIDE, ACTION_ITEMS)

---

## 4. Role Activation — Two Entry Paths

### 4a. Button / Text Input (full control)
User taps `🎭 Set Role` button in AssistantPanel → `RoleSetupModal` opens → user fills:
- `role_name` (e.g. "Venture Capitalist")
- `role_description` (e.g. "Series B investor who focuses on SaaS, skeptical of B2C pivots, always asks about unit economics")
- `sensitivity` (defaults to `smart`)

On Activate: `POST /api/role/set` → role badge appears → Jarvis sends an in-character acknowledgement message.

### 4b. Voice Command (zero-friction, no modal)
User says *"Hey Jarvis, act as a venture capitalist"* mid-meeting:
- Orchestrator routes to `PLAY_ROLE` → detects no active role → treats as `SET_ROLE`
- `role_name` extracted from command text
- `role_description` auto-generated by the brain using meeting transcript context (what has been discussed so far)
- `sensitivity` defaults to `smart`
- Jarvis replies in-character: *"Activating Venture Capitalist mode. Describe the character further in the role panel anytime."*
- Frontend receives the activated role → badge appears, watcher starts — no modal interruption

### 4c. Exiting
- Voice: *"Hey Jarvis, exit role"* / *"stop role"* / *"be yourself"*
- Button: tap `✕` on the `RoleStatusBadge`
- Automatic: meeting ends (`meeting_phase = meeting_end`)

## 7. Role Setup Modal — Field Spec

| Field | Type | Validation |
|-------|------|-----------|
| `role_name` | string | 1–60 chars, required |
| `role_description` | string | 20–1000 chars, required |
| `sensitivity` | enum | `major_only` \| `smart` (default) \| `frequent` |

---

## 8. Watcher Agent — Signal Detection Logic

```
Sensitivity → signal thresholds

major_only:  only "decision" signal triggers response
smart:       "decision" + "risk" + "disagreement" trigger response   ← default
frequent:    any strong assertion also triggers

Rate limit: 60 seconds minimum between proactive responses (all sensitivities)
Chunk minimum: 20 words before analysis runs
Hash dedup: sha256 of stripped chunk prevents re-analysis
```

---

## 9. Enhanced Role Agent — Response Structure

```json
{
  "reply": "in-character response (structured, grounded in transcript)",
  "role": "Venture Capitalist",
  "signal_type": "decision | risk | disagreement | on-demand | entry",
  "follow_up_questions": [
    "What is your 12-month NRR?",
    "Who owns the enterprise motion?"
  ]
}
```

`follow_up_questions` render as tappable chips below the `RoleBubble`. Tapping one sends it to Jarvis as a new message in the role context.

## 10. UI State Machine

```
No Role Active
  └── SetRoleButton visible
  └── RoleStatusBadge hidden

Role Setup Modal Open
  └── user fills name + description + sensitivity
  └── Activate → POST /api/role/set

Role Active
  └── RoleStatusBadge visible ("🎭 {name}  ✕")
  └── SetRoleButton hidden
  └── useRoleMode watcher running (12s interval)
  └── All Jarvis messages answered in character
  └── Proactive RoleBubbles appear when high-signal detected

  EXIT paths:
  ├── user clicks ✕ on badge
  ├── user says "Hey Jarvis, exit role" / "stop role" / "end role"
  └── meeting ends (meeting_phase = meeting_end)
```

## 11. Voice Command Additions (orchestrator routing)

New keywords added to `_route_intent` fast-path:

```python
# Exit role
if any(k in lower for k in (
    "exit role", "stop role", "end role", "leave role",
    "stop acting", "stop playing", "be yourself", "normal mode",
)):
    return "EXIT_ROLE"
```

`EXIT_ROLE` handled in `run_execute` → calls `SESSION_STORE.clear_role` → returns out-of-character ack.

---

## 12. Anti-Regression Checklist

- Existing SUMMARY, NOTES, BRAINSTORM, HELP_DECIDE, ACTION_ITEMS routes: unchanged
- Role injection is additive only — no existing prompt overwritten
- `/v1/execute` schema: unchanged (new endpoints are separate)
- meet-mind proxy pattern: identical to existing `assistant_client.py` pattern
- TTS: role proactive responses pass through the same TTS pipeline as regular responses
